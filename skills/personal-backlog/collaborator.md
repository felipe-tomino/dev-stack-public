# Collaborator reporting

Apply this reference as an executor or whenever no assistant-manager role is explicitly assigned. Read [SKILL.md](SKILL.md) for the shared read, safe comment/reference append and readback procedures. Runtime, engine/model identity and CLI access do not change this role.

## Identify the existing commitment

Read existing tasks assigned to you or reliably identified as relevant to the authorized work. Match the actual outcome, source context and current instructions; a similar title alone is not enough. Use the returned task ID and read its full details before reporting. Read only the context needed for that work; queue access does not authorize a general backlog-management pass.

If no relevant existing task can be reliably identified, deliver progress, blockers and evidence to the user or manager instead. Do not create a task or block otherwise authorized execution waiting for an ID.

## Append a report, preserve management state

When reporting is authorized, use only the common `--comment` with `--comment-author` and optional `--add-ref` procedure on that existing task. Attribute the report to the actual executor and role, include the date, and distinguish what you observed from claims or inference. State the completed scope, meaningful evidence/artifact links, verification performed and remaining limits. For blockers, include the cause and unblock condition under the common reporting rules. Report the assigned slice as a slice, even when your own work is finished.

Collaborators do not create tasks, reprioritize work, check or uncheck acceptance criteria, edit task metadata/status/dependencies/assignees/descriptions/notes/plans/final summaries, change task lifecycle, close or delete tasks. Adding an attributed report/reference is the only permitted queue mutation. Suggest a necessary management change in the report rather than applying it. Do not rewrite prior reports or other contributors' evidence.

Read back the append under the common concurrency rules. Finish by delivering the evidence and unresolved limits to the user or manager; the manager evaluates the whole commitment and promotes state. Reporting does not grant permission for extra execution, messages, schedules or other side effects.
